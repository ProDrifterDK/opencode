## Implementation Summary

### FileScopeGuard Service
- `FileScopeEntry` schema: binds sessionID + engineerID + file scopes (glob patterns)
- `ScopeDeniedError`: tagged error raised when engineer edits out-of-scope files
- `Service` (Context.Service pattern with `@opencode/FileScopeGuard` tag):
  - `register(entry)`: registers an engineer session with file scopes
  - `unregister(sessionID)`: removes engineer scope restrictions
  - `check(sessionID, filePath)`: validates file access, notifies lead on violation
  - `isEngineer(sessionID)`: synchronous check if session is a registered engineer

### Scope Matching
- Uses `Wildcard.match` from existing `@/util` (same as permission system)
- Patterns like `src/auth/**` match all files under src/auth/
- Pattern `src/**` matches everything under src/

### Hook Integration
- `beforeToolExecute(getSessionID, getService)`: returns a `(toolID, args) => Effect` function
- Guards edit, write, bash tools only
- Extracts file path from tool args (filePath or path property)
- Skips non-engineer sessions and non-guarded tools silently
- Denies with ScopeDeniedError on out-of-scope access

### Mailbox Notification
- On violation: sends urgent "scope_violation" message to lead mailbox
- Uses `Effect.catch` to gracefully handle mailbox failures
