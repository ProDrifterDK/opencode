# Team Status

Retrieve and display the current status of the active team using the
`team_*` LLM tools. You are the Lead of the session that invoked this
command; only the Lead can call `team_monitor` on a team it owns.

## Step 1: Identify the Team

If `$ARGUMENTS` contains a team ID (format: `tm_*`), use that.

Otherwise you must already know the active team's ID from the current
conversation — when `/team-start` was run, `team_create` returned a
`teamID` which should still be in context. If you truly don't have one,
tell the user: "No team ID known in this session. Run `/team-start
<goal>` or pass a team ID: `/team-status <tm_...>`."

## Step 2: Fetch Progress

Call:

```
team_monitor({ teamID })
```

The output contains fields equivalent to a progress report: total,
pending, inProgress, completed, failed, blocked counts, plus an
`engineers` array summarising each slot's state and current task, and
a `blockers` array for blocked tasks.

Then call:

```
team_roster({ teamID })
```

to get full engineer details (name, session ID, current task, last
heartbeat). `team_roster` exposes the same information a direct
`listTeamEngineers` call would — use its output to augment the display
below.

## Step 3: Format Output

Render a formatted table combining the two results. This is the shape a
past version of this prompt called a `ProgressReport`:

```
╔══════════════════════════════════════════╗
║ Team Status: <teamID>                    ║
╠══════════════════════════════════════════╣
║ Tasks: <completed>/<total> completed     ║
║ Pending: <n> | In Progress: <n>          ║
║ Failed: <n> | Blocked: <n>               ║
╠══════════════════════════════════════════╣
║ Engineers:                                ║
║   <name> [<state>] — <task or idle>      ║
║   (last heartbeat: <ago>)                 ║
║   ...                                     ║
╠══════════════════════════════════════════╣
║ Blockers:                                 ║
║   <task title> blocked by <reason>        ║
║   ...                                     ║
╚══════════════════════════════════════════╝
```

No fancy summary formatter exists server-side — the previous version of
this prompt referred to a `formatStatus` helper, but in reality the
formatting is your job. Do it here in the prompt based on the two tool
outputs above.

## Error Handling

- If `team_monitor` fails with "Team not found": report "Team not found:
  `<teamID>`" and stop.
- If `team_roster` fails but `team_monitor` succeeded, render the
  progress table without engineer details and note that the roster
  lookup failed.
- If the Lead-only check fails ("Only the lead can…"), the invoking
  session is not the Lead of that team — tell the user and stop.
