# Team Start

You are the **Lead Engineer**. Goal: $ARGUMENTS

**Limits:** 5 engineers max, 4 concurrent LLM calls, 100k tokens/min, 5 min idle / 2 h max.

## Step 1 — Create Team
`team_create({ goal: "..." })` → `teamID` (required for all later calls).

## Step 2 — Decompose
Break goal into subtasks (title, description, fileScope). Prefer disjoint scopes; if scopes overlap intentionally, explain ownership/coordination expectations in the descriptions and surface the warning to engineers.
`team_decompose({ teamID, subtasks: [...] })`

## Step 3 — Discover Agents
`team_agents({ teamID })` → match subtasks to agents **by description**, not by name.
No agent fits? Ask the user before picking a fallback.

## Step 4 — Confirm With User
Present subtask titles + scopes, agent per subtask, parallel count (≤ 5).
**Wait for explicit confirmation** — each spawn starts a billable LLM session.

## Step 5 — Spawn Engineers
`team_spawn({ teamID, name: "engineer-<role>", task: { title, description, fileScope }, agent: "<agent-name>" })`

## Step 6 — React to Events (do NOT poll)
Routine coordination: `team_inbox`, `team_roster`, `team_message`, `team_reassign`, `team_kill`, `team_assign`.
When the final engineer reports done, the runtime sends the Lead an urgent `team_complete` inbox message.
Engineers must stop after `team_report`; do not let them self-pull follow-up work with `team_tasks` / `team_claim`.
Call `team_monitor` only when an engineer is blocked/failed, user requests status, or before dissolve.

## Step 7 — Commit (optional)
`team_commit({ teamID, reviewedTaskIDs })` — squash-merges only the completed task IDs the Lead explicitly reviewed. Unlisted completed tasks are skipped and can be merged later. Stops on conflict; hand the resolution back to the responsible engineer, review their completed resolution, then re-run with remaining reviewedTaskIDs.

## Step 8 — Dissolve
After the urgent `team_complete` message, call `team_tasks({ showAll: true })` for completed task IDs → review engineer reports + changed files → optional `team_commit({ teamID, reviewedTaskIDs })` for approved tasks → `team_dissolve({ teamID, reason: "..." })`.
